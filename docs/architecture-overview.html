Tech Stack

Angular 17 Standalone Components Supabase (Auth + DB) localStorage-first XorShift PRNG html2canvas

The app manages a single badminton session: add players, shuffle them into balanced doubles matches across courts, confirm results, track win/loss and round counts, and split the bill at the end. All mutable state lives in localStorage first and is asynchronously synced to Supabase for cloud persistence and guest viewing.

State: localStorage + Supabase Dual-Write

Components hold local copies of Maps / arrays. Every mutation is written to localStorage synchronously, then a fire-and-forget async call upserts the same data to Supabase. There is no reactive stream — components re-assign their local copies after each service call.

Player fields

  • rank — manual skill rank 1 (strongest) – 10 (weakest), default 5. Drives effectiveRank in the shuffle.
  • totalRoundsPlayed — scheduling priority (who plays next)
  • actualTotalRoundsPlayed — used for bill split + win-rate
  • teamateHistory — ordered log of every teammate ever (recency via lastIndexOf)
  • roundsWaited — consecutive sat-out rounds (resets to 0 on break)
  • status — 'ready' | 'break' | 'selected'
  • lastWonMatch — courtNo:timestamp dedup guard for win toggling

Match fields

  • status — 'available' | 'playing' | 'done'
  • mode — which shuffle mode produced this pairing (balanced/mixed/novel), shown in UI
  • whoWon — 'teamA' | 'teamB' | ''

Shuffle Modes & Constraints

Effective Rank effectiveRank(player)

Lower = stronger: rank * 1000 - winRate * 2000, where winRate = (roundsWon + 1) / (actualTotalRoundsPlayed + 2) (Laplace-smoothed). A high win-rate can shift a player up to 2 full rank tiers above their manual rank.

Mode A — Balanced

shuffleBalanced / formQuadPairs

  1. Sort eligible players by effectiveRank
  2. Split into quads via interleaving (sorted index i → quad i % numQuads) so every quad spans the full skill range
  3. Within each quad: if a force-pair exists, pair them + remaining two (unless nemesis-blocked → returns null, whole shuffle falls back to Novel)
  4. Else try 3 splits — [0,3]v[1,2], [0,2]v[1,3], [0,1]v[2,3] — across 5 progressively-relaxed passes (rank diff ≤3 + no nemesis + no recent repeat → ... → nemesis-only)

Mode B — Mixed

shuffleMixed

  1. Lock force pairs first (lockForcePairs)
  2. Sort remaining players by effectiveRank
  3. Pair strongest with weakest, working inward (top↔bottom)

Mode C — Novel

shuffleNovel

  1. 10 attempts; cooldown offset = ceil((attempt+1)/3), capped at 4
  2. Force pairs locked first; nemesis pairs hard-excluded
  3. Greedily pick partner with lowest noveltyScore (recent-teammate + recent-opponent penalty)
  4. Keep the attempt with the lowest total score

Auto mode

resolveMode()

Rolls rng.random() * 100 against shuffle-mode-weights (default {balanced: 60, mixed: 30, novel: 10}) to pick a mode each shuffle. Configurable on the Settings page.

Shared constraint helpers

  • isRecentTeammatePair(a, b, totalPlayers, offset) — true if a.totalRoundsPlayed - lastTeammateIndex < max(1, totalPlayers - offset)
  • isNemesisPair — checked via a player1:player2 / player2:player1 set; always excluded, never just penalized
  • Force-teammate pairs honored whenever both players are in the eligible window
